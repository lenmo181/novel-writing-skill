# 常见问题与故障恢复（v7.31）

这里集中放新手最常遇到的问题。先看“现象”，再按“恢复动作”处理；不要为了绕过错误直接删除项目档案或强行标记完成。

## 先做哪一步？

如果不确定是技能包、路径还是小说项目出了问题，先在技能目录运行：

```powershell
python tools/doctor.py
python tools/doctor.py --json
```

`doctor.py` 只读检查目录骨架、必需文件、版本日期、Python 语法和技能包内相对引用；它不联网、不读取小说项目，也不会替你更新技能。需要修复时，再按报告选择 `sync_skill.ps1`、`lint_skill.py` 或 `check_refs.py`；怀疑某个脚本启动即闪退时，追加 `python tools/doctor.py --runtime-smoke`。

## 使用与触发

### 1. 我不知道该怎么开始？

直接说目标即可，例如：

```text
初始化项目，书名《XXX》，题材悬疑，预计50万字
写第1章，标准级
审校第12章，重点看节奏和逻辑
```

缺少的非关键字段会先生成草案并标 `[待确认]`；会改变主线、结局或重大人物命运的字段必须先问你。

### 2. 规则很多，我需要全部背下来吗？

不需要。普通用户只需记住“初始化项目 → 写第1章 → 续写”。技能自动执行基础校验；只有你明确要求审校、去 AI 味、全书检测、体检、封面或更新时，才读取对应手册。工具职责见[工具选择](工具选择.md)，规则真源和阈值由技能内部维护，不建议在聊天里重复粘贴旧数值。

### 3. `doctor`、`lint`、`check_refs`、`release_check` 是不是重复？

不是同一个层级：`doctor.py` 是安装后总入口，`lint_skill.py` 查版本和默认值漂移，`check_refs.py` 查悬空引用，`release_check.py` 是发布前汇总门。日常先跑 `doctor.py`，只有报告点名某一类问题时再补对应工具；完整矩阵见[工具选择](工具选择.md)。

### 4. 同时说“续写并审稿”会走哪条流程？

按一个复合主流程执行：先续写，再审稿，发现红线就修复并复测，达标后才记入断点。若只说“续写”，按标准级完成一章；若只说“审稿”，不改正文，除非你明确授权修订。

触发优先级为：

1. 明确的技能更新/安全操作；
2. 明确的主要动作（写、审校、去 AI 味、拆文、封面、体检）；
3. 泛化请求（“帮我看看”“继续”）才读取当前项目断点并先给最小下一步。

一个请求只选择一个主路由，相关检查作为该路由的步骤，不并行启动多个重型流程。

### 5. 快速级、标准级、深度级怎么选？

| 级别 | 什么时候用 | 会做什么 |
|---|---|---|
| 快速级 | 试写片段、改一句/一段、只要方向草稿 | 最小上下文 + 基础格式检查，不登记为正式完章 |
| 标准级 | “写第 X 章”“续写”“完整交付”（默认） | 约束锁、正文、机械 13 项、语义 17 项、档案和断点 |
| 深度级 | 明确说“深度审校/全书/批量/看板/转剧本” | 标准级之外增加全书工具、差异/连续性、可选外部检测 |

你不必在每次请求里写级别；只有想改变默认行为时再指定。

## 文件、项目与断点

### 6. 技能安装后是不是全局调用？

放在当前用户的 `~/.codex/skills/网络小说创作技能/` 后，它对该用户的 Codex 会话可发现；它不是操作系统级服务，也不会对所有普通问题自动运行。只有请求匹配网文创作或维护意图时才触发。更新文件后重启 Codex 或重新加载技能列表即可看到新内容。

如果技能目录存在但界面仍找不到，先确认 `doctor.py` 通过，再执行 `powershell -ExecutionPolicy Bypass -File tools/sync_skill.ps1 -WhatIf` 查看目标路径；确认无误后去掉 `-WhatIf` 同步，最后重启 Codex。

### 7. 我有旧稿，为什么不能直接说“续写”？

可以，但先说“导入旧书”或“初始化续写”，让技能把旧目录映射到 `mind/` 七档案。已有正文只读；缺项标待补充，不凭空补设定。迁移完成后再说“续写第 X 章”。

### 8. 如何恢复上次进度？

直接说“续写”或“接着写第 X 章”。技能读取 `mind/章节目录.md` 的进度行、最近单章回顾和当前走向锁定；已完成章不会重写。若进度行和正文目录冲突，先报告冲突并让你裁定。

### 9. 哪些文件会被改动？

写章通常只改当前项目的 `书稿/`、`mind/`（以及按项目需要的 `剧本/`）。只读体检、连续性检查、上下文包和差异分析不应静默覆盖原档案。技能更新器只改 Codex 技能安装目录，不碰小说项目。

## 校验、检测与隐私

### 10. “检测失败”和“检测不达标”有什么区别？

- **不达标**：脚本能完成检测，但发现硬伤；修正文稿后重跑。
- **检测失败**：输入错误、文件不存在、参数非法或外部 API 超时；先修复环境/参数，不能把失败当成通过。
- **未检测**：没有 Key、没有外部同意或服务不可用；保留可见标记，继续使用本地检查，不伪装成“人类分达标”。

### 11. 没有 API Key 或下载不了墨尺能不能写？

能。朱雀/墨尺是可选检测通路；没有 Key 或下载不了墨尺时，仍可执行本地 `check_chapter.py` 和免依赖粗测：

```powershell
python tools/check_chapter.py "书稿/第001章_章节名.md" --ai-lite
```

它给出启发式指标，不替代第三方模型结论，但足够用于先筛出句长、段长、比喻词和情绪词等明显风险。需要朱雀时，先说明正文会离开本机，再由你明确同意；Key 只放当前进程环境变量，不写入技能或项目。

### 12. 为什么脚本退出码是 1/2/3？

| 退出码 | 含义 | 下一步 |
|---|---|---|
| 0 | 检查通过 | 可以进入交付/归档 |
| 1 | 质量硬伤或阈值未达标 | 按报告定位修复，重新运行同一命令 |
| 2 | 输入、路径或参数错误 | 检查文件路径、项目根和参数；不要反复改正文 |
| 3 | 外部服务/API/网络失败 | 留痕为“未检测”，改用本地流程或稍后重试 |

## 故障恢复表

| 现象 | 原因判断 | 自动处理 | 你需要提供/决定 |
|---|---|---|---|
| 找不到项目 | 路径不存在或未指定 | 报告解析后的路径，不猜另一本书 | 给项目根；只有“初始化项目”才创建新目录 |
| 找不到目标章 | 章纲或正文没有该章 | 停止写正文并列出缺口 | 确认补纲、换章号，或授权导入旧稿 |
| `check_chapter.py` 退出 1 | 正文存在硬伤 | 保留草稿，定向修复后复测 | 若三轮仍不达标，决定移交人工或调整要求 |
| 脚本退出 2 | 文件/参数错误 | 不更新完成进度 | 修正命令或路径 |
| 朱雀/其他 API 超时 | 外部服务不可用或未授权 | 标记未检测，不改变本地结论 | 同意重试、改本地检测，或稍后再试 |
| 会话中断 | 只完成了部分步骤 | 只把已落盘且已校验的章记为完成 | 下次说“续写”；未完成草稿先复核 |
| 改稿删掉超过 10% | 可能影响伏笔/钩子 | 生成差异报告并暂停自动归档 | 确认保留、回滚或继续大修 |
| 更新包版本低于本地 | 远端缓存或降级包 | 拒绝降级，不覆盖本地 | 等远端更新或指定可信包 |
| 更新下载/解压/替换失败 | 网络、包损坏或路径不安全 | 保留当前版本，失败自动回滚；旧版备份留在备份目录 | 先检查报告，再决定重试；不要手动删备份 |

## 技能更新最短路径

```powershell
python tools/update_skill.py --check --json
python tools/update_skill.py --update       # 会先询问
python tools/update_skill.py --auto         # 仅在你明确授权自动更新时
```

检查只读远端版本；更新会先下载到临时目录、校验包内版本和 ZIP 路径、备份当前版本，再替换。当前版本较新时不会降级。更新后如果界面仍显示旧规则，重启 Codex。

## 自检命令

```powershell
python tools/doctor.py
python tools/lint_skill.py
python tools/check_refs.py
```

三条都通过，说明安装结构、版本、关键阈值和技能包内引用一致。它们不读取小说正文，也不会修改项目。
