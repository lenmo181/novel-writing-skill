# 事实台账（v7.49）

> 定位：`mind/七档案` 管「现在是什么样」，事实台账管「哪些事是真的、什么时候成立、欠着什么时候还」。
> 两者互补：快照层保证不穿帮，台账层保证因果链不断、数字不打架。

## 一、为什么需要

长篇写到几百章，两类翻车最难靠通读发现：

1. **数字打架**：第 30 章说欠三百两，第 200 章说欠三十两。通读几百章才能撞上，而那时改的成本极高。
2. **承诺失踪**：第 12 章埋了"三个月后回来"，到第 90 章没人提。伏笔追踪表管编号类伏笔，
   但**非伏笔形态的事实性承诺**（欠款、伤情期限、契约到期、身份时效）没有登记处，就会静默烂尾。

三个开源项目在这个交集上给了同一类答案：

| 项目 | 对应实现 | 可借鉴点 |
|---|---|---|
| chinese-novelist-skill | 设定与事实词典 | 先登记后写；到期必兑；数字事实优先登记 |
| AI_NovelGenerator | `entity_state_history` | 实体状态随章推进留痕，而不是只存当前值 |
| MuMuAINovel | 伏笔状态机 + 三层提醒 | 状态机 + 到期/超期分层，不是一刀切 |

本技能只吸收**确定性的、可脚本核验**部分，不引入向量库、不引入实体图。

## 二、台账文件

路径：`mind/事实台账.md`（由 `tools/init_project.py` 自动生成骨架）

```markdown
| 编号 | 事实 | 类型 | 位置 | 未知原因 | 登记章 | 到期章 | 状态 | 依据 |
|---|---|---|---|---|---|---|---|---|
| FL-001 | 刀藏在床底第三块砖下 | 物品 | chapter_before:3 |  | 第1章 | 第3章 | 待回收 | 第001章 |
| FL-002 | 老刀欠债三百两 | 数字 | book_start |  | 第1章 |  | 已登记 | 第001章 |
| FL-003 | 血玉下落 | 物品 | unknown:needs_review |  | 第1章 |  | 已登记 | 第001章 |
```

### 列语义

| 列 | 取值 | 说明 |
|---|---|---|
| 编号 | `FL-001` 起 | 与伏笔编号（`F-xxx`）区分，避免同号两义 |
| 事实 | 一句话 | **必须可判定真假**——不写"气氛紧张"这类无法核验的句子 |
| 类型 | 数字/设定/状态/关系/物品/地理/时间 | 「数字」类型受"数字事实优先登记"约束 |
| 位置 | 见下 | 事实何时成立 |
| 未知原因 | `nonexistent`/`unclaimed`/`before_start`/`voided`/`needs_review`/`unresolved_reference` | 仅当位置为 unknown 时需要 |
| 登记章 | 第N章 | 先登记后写的锚点：这一章登记的事实，就是这一章之后不能改的 |
| 到期章 | 第N章 | 承诺兑现的章号；到期未兑现 = 到期必兑违规 |
| 状态 | 已登记/已兑现/待回收/已作废/不适用 | 「待回收」才参与到期判定 |
| 依据 | 章节号/设定文件/考据条目 | 指向可回溯的来源 |

### 位置语义

| 写法 | 含义 |
|---|---|
| `book_start` | 开书即成立 |
| `volume_start` | 某卷开始成立（可带卷号：`volume_start:3`） |
| `chapter_before:12` | **必须在第 12 章之前成立** |
| `chapter_after:12` | 第 12 章之后才成立 |
| `unknown:needs_review` | 位置未知，原因写在参数或「未知原因」列 |

**位置不是装饰**——它决定事实何时成为约束：
`chapter_before:12` 的事实在第 12 章还没交代，就是漏了。

## 三、三条工作纪律

### 1. 先登记后写

新事实**先入台账，再在正文落地**。顺序反了会产生"既成事实"无法回滚。

典型场景：第 40 章临时起意写"老三其实是断了三根手指"，但第 12 章已经写过"老三右手齐全"。
登记第 40 章时，位置写 `chapter_before:13` → 核验立刻报冲突。

### 2. 到期必兑

写了「到第 60 章还你」就得在第 60 章还。`到期章` + `状态=待回收` 组合即构成承诺；
过了到期章仍未兑现，核验报 `FACT_DUE_UNPAID`。

**改期要留依据**：确实还不了时，把 `到期章` 改到新章号，并在 `依据` 列写明改期原因——
静默改期等于把问题藏起来。

### 3. 数字事实优先登记

数字是长篇最容易打架的一类（金额、伤情、天数、距离、兵力）。

凡正文要出现具体数字，**先登记再写**。核验会扫全书里"数字+量词"（如"三百两""12枚""三天"）
的强数字信号，出现频次高但台账里查不到的，告警提示补登记。

> 口径保守：只认「数字+量词」这类强信号，纯数字串（年份、门牌号）不单独计——
> 否则噪声会淹没真问题。

## 四、怎么查

```bash
python tools/fact_ledger.py "<项目根>"            # Markdown 报告
python tools/fact_ledger.py "<项目根>" --json     # 机器可读
python tools/fact_ledger.py "<项目根>" --strict   # 有任意问题即退出码 1
```

`tools/project_health.py` 已把台账核验并入汇总（来源标记 `fact_ledger`）。

### 检查项一览

| 编号 | 级别 | 含义 |
|---|---|---|
| `FACT_LEDGER_MISSING` | 警告 | 项目还没有事实台账 |
| `FACT_ID_DUP` | 中 | 编号重复 |
| `FACT_ID_MISSING` / `FACT_TEXT_MISSING` | 中 | 缺编号或缺事实描述 |
| `FACT_TYPE_UNKNOWN` | 低 | 类型不在白名单 |
| `FACT_POSITION_BAD` | 低/中 | 位置语义非法；或 `chapter_before/after` 缺章号参数 |
| `FACT_UNKNOWN_REASON` | 中/低 | 位置为 unknown 但未填合法原因；或原因不在枚举内 |
| `FACT_REASON_STALE` | 低 | 位置非 unknown 却填了未知原因 |
| `FACT_STATUS_BAD` | 低 | 状态不在白名单 |
| `FACT_CHAPTER_BAD` | 低/中 | 登记章/到期章不是合法章号；或到期章早于登记章 |
| `FACT_DUE_UNPAID` | 中 | **到期必兑违规**：已过到期章仍未兑现 |
| `FACT_DIGIT_UNREGISTERED` | 低 | 数字事实未登记（先登记后写） |

## 五、写入边界

**本工具只读**。它只报告"哪些事实没登记、哪些到期没兑现"，**不替作者决定剧情**、
不改写正文、不自动补全台账、不删改既有记录。

写入由作者或 AI 按本文协议改 `mind/事实台账.md`。
这与其他档案工具一致：`continuity_check.py`、`fact_ledger.py`、`project_audit.py` 全部只读，
只有 `init_project.py`、`write_chapter.py` 一类才是写入通道。

## 六、与既有档案的关系

| 档案 | 管什么 | 与台账的关系 |
|---|---|---|
| `mind/角色状态快照.md` | 角色现在在哪、持有什么、知道什么 | 台账记"持有物从哪来、欠着什么时候还" |
| `mind/伏笔追踪表.md` | 编号型伏笔的埋设与回收 | 台账管**非伏笔形态**的事实性承诺 |
| `mind/时间线.md` | 故事内时间推进 | 台账的「登记章」是**写作进度**轴，不是故事内时间 |
| `mind/锚点日志.md` | 章节锚点留痕 | 台账的「依据」列常指向锚点日志条目 |

**不要用台账替代伏笔表**：需要读者"等着回收"的东西走伏笔表（带 Tier 与钩子设计），
只是"不能忘"的事实走台账。两套编号（`F-` / `FL-`）刻意分开，就是为了让"该伏笔化的"和"只要别忘的"泾渭分明。
