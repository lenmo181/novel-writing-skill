# 导入旧书手册（逆向工程成可续写工程）

> 触发：`导入这本书/把我的txt接入流程/继续写这本旧书`。目标：把已写的书反向解析成 mind/ 档案齐全的标准项目，从断点续写。

## 四阶段流程

### Phase 1 确认导入源
1. 输入识别：单文件txt / 目录多文件 / 用户直接贴文本
2. 篇幅自动检测：用户显式声明 > 章节结构信号 > 字数兜底；按长篇/短篇分流
3. 残稿判定：标"已完结"但正文戛然而止、或中途断章 → 记录断点位置，问用户"从残章续写还是先补完"（只记录，不替用户选）
4. 目标确认：建成"可续写工程"还是"仅拆文库"——不确定就问，不默认

### Phase 2 深度分析
- 按《拆文手册》完整管道跑一遍，**用"完整拆解、一次跑完、不停下询问"契约**
- 必备产物：`剧情/节奏.md` + `剧情/情绪模块.md`，缺了先修复重跑
- 中断恢复：`_progress.md` 记录阶段和最后处理章节

### Phase 3 迁移
**长篇10步**：
1. 按《项目模板》建目录骨架
2. 正文标准化：`书稿/第XXX章_章名.md`，章号补零对齐，**内容一字不改**
3. 角色迁移+分级：主角=出场章≥50%且推动主线；核心配角=≥20%；功能角色=<20%简化
4. 关系整理进 `设定/角色.md`
5. 世界观同步（力量体系<200字的并入背景设定）
6. 大纲反推：从正文反推卷纲/章纲；**卷划分用户确认制**——原文有卷界按卷界分，无卷界展示候选切分方案等确认，不机械硬切
7. 无法判断的设定字段统一标 `[待补充]`，**禁止编造**
8. mind/ 六档案初始化：快照/锚点/伏笔表从正文反推；`章节目录.md` 逐章登记实际字数；时间线双视图（作者真相+读者已知）
9. **不伪造旧章的逐章记录**：状态快照以"最后完整章"为基准，之前的章不倒填
10. 对标隔离：导入书进 `拆文库/`，**不得登记为自己的对标**

**短篇4步**：单文件 `正文.md` + `设定.md`（核心框架+**本书续写基线**两区块）+ `小节大纲.md`（按段反推）→ 严禁误建长篇目录（追踪/大纲/正文/）

### Phase 4 激活
- 质量检查：长篇7项（章节命名对齐/档案齐全/时间线双视图隔离/`[待补充]`清单…）；短篇3项（单文件格式/未误建长篇目录/续写基线明确）
- 输出完成报告：导入统计+待补充清单
- 确认后即可 `续写`（从最后完整章+1开始）

## 特例

- **旧项目只有零散档案**：只重建缺失档案，不重拆全书（数最后完整章→从旧档案+近3-5章正文重建状态）
- **超大书（>200章）**：首期深拆前50章+全书概要即可激活续写，其余章节200字/章简化摘要，追踪初始化必须覆盖全部已写章节
