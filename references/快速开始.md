# 3 分钟快速开始与完整写作示例（v7.28）

这份手册给第一次使用的人看。你不需要记住校验规则，也不需要先选择几十个模式；先用一句自然语言说明目标，技能会选择一个主流程，并在需要时提示下一步。需要更完整的“输入→动作→产出”对照时，继续读[操作范例](操作范例.md)；不知道该选哪条流程时读[模式操作卡](模式操作卡.md)。

## 先记住三条

1. **一次只选一个主流程**：写、审校、去 AI 味、拆文、封面、体检和更新是不同入口；同一句话同时出现多个动作时，按主动作执行，其他动作只作为明确的后续步骤。
2. **完整章节默认标准级**：说“写第 X 章/续写”会完成写作、机械校验、语义复核和档案更新；只要片段或草稿时才用快速级；“深度审校/全书检测”才进入深度级。
3. **遇到问题先看结果码**：`1` 表示质量硬伤，修复后重验；`2` 表示输入或参数问题；`3` 表示外部服务失败，不等于正文通过或不通过。集中处理见[常见问题](常见问题.md)。

## 3 分钟流程

### 1. 开新书

最小输入只需要书名、题材和规模：

```text
初始化项目，书名《雾城拾荒者》，题材都市悬疑，预计80万字，默认番茄
```

技能会：

- 创建 `书稿/`、`大纲/`、`设定/`、`mind/` 等项目骨架；
- 生成世界观、主角卡、四级大纲的草案；
- 把缺少的内容标为“待确认”，不会假装成用户已经决定的设定；
- 停在“设定与大纲确认”这一安全点，不会未经确认直接写长篇正文。

你也可以一次补充设定：

```text
主角：沈砚，旧城修表匠，怕欠人情；金手指：能听见旧物最后一句话；禁写：真实政治事件。
```

### 2. 写第一章

```text
写第1章，写完按标准级检查，章末留下悬念钩子
```

执行顺序固定为：

1. 读取当前章纲、角色状态、时间线和最近回顾，建立一行约束锁；
2. 以“目标→阻碍→转折”安排 2-4 个场景，正文只使用已确认设定；
3. 写入 `书稿/第001章_章节名.md`，标题按实际章末钩子命名；
4. 运行 `tools/check_chapter.py`，再做 30 项语义复核；
5. 有硬伤就地修复并复测，合格后更新 `mind/章节目录.md`、角色/伏笔/时间线和 `mind/回顾/第001章回顾.md`；
6. 回复只给约束锁、校验摘要、产出文件和下一章断点，不重复粘贴整章正文。

### 3. 继续连载

```text
续写第2章，沿用上一章断点；如果章纲缺失先补纲，不要自行改结局
```

已有项目只需给项目根目录或当前工作目录。技能会优先读取 `mind/章节目录.md` 的进度行；找不到项目或章节时会停下报告路径，不会把另一个项目当成当前书。

## 完整端到端示例

### 用户输入

```text
初始化项目，书名《雾城拾荒者》，都市悬疑，预计80万字。
主角沈砚是修表匠，能听见旧物最后一句话；第一卷围绕一只停在23:17的怀表展开。
确认大纲后写第1章，标准级，字数按默认范围。
```

### 技能应做的事

| 阶段 | 可见动作 | 产出/验收 |
|---|---|---|
| 初始化 | 建骨架，生成草案并标待确认项 | `大纲/`、`设定/`、`mind/` 七档案 |
| 确认 | 只锁定用户确认过的世界规则和第一卷走向 | `mind/剧情走向锁定.md` |
| 写前 | 读取第1章章纲，登记 `主角-听见-怀表遗言` 钩子指纹 | 约束锁 + 场景目标/阻碍/转折 |
| 写作 | 生成正文并按手机端段落排版 | `书稿/第001章_停在2317.md` |
| 校验 | 机械脚本 + 语义复核；失败则定位病灶段落 | 退出码 0 才允许交付 |
| 归档 | 更新目录、状态、伏笔、时间线、单章回顾 | 断点：已完成第1章，下一章第2章 |

### 合格时的最短回执

```text
已完成第1章《停在2317》
校验：check_chapter.py 退出码 0；语义复核 30/30；AI 味指数 4/10
已更新：mind/章节目录.md、角色状态快照.md、伏笔追踪表.md、回顾/第001章回顾.md
【断点】已完成至第1章 | 下一章：第2章 | 待办：确认怀表遗言的第二个信息点
```

### 失败时的最短回执

```text
第1章暂不交付：check_chapter.py 退出码 1
问题：字数不足、章末钩子与章纲指纹不一致
处理：保留当前草稿，补足冲突场景并重写章末两段；修复后重新校验，未更新完成进度
```

## 各模式的最小输入与产出

| 目标 | 最小输入 | 默认产出 |
|---|---|---|
| 写/续写长篇 | 项目 + 章节号或“续写” | 正文、校验摘要、档案更新、断点 |
| 写短篇 | 题材/核心冲突/字数（缺项可让技能给选项） | 短篇正文、平台格式检查 |
| 写短剧/转剧本 | 原文或题材、集数/单集时长 | 分集剧本、场景和卡点检查 |
| 拆文/扫榜 | 作品或榜单范围、想研究的维度 | 结构/写法档案，不复制正文 |
| 审校/去 AI 味/通读 | 文件或章节范围、优先问题 | 修订稿、变更清单、待确认项、报告 |
| 体检/连续性 | 项目根目录 | 只读报告和问题编号，不静默改档案 |
| 封面 | 书名、笔名、平台、题材 | 图片或可执行提示词 + 质检结果 |
| 更新技能 | “检查更新/更新技能” | 版本比较；更新时备份、校验、回滚 |

## 安装后自检

在技能目录执行以下命令即可确认安装完整：

```powershell
python tools/doctor.py
python tools/doctor.py --runtime-smoke
python tools/lint_skill.py
python tools/check_refs.py
```

看到结构、版本、语法、默认值和引用均通过后，再开始初始化项目。市场包中 `tools/` 可能按平台规范显示为 `scripts/`，使用方式相同。

## 什么时候停下来等用户

- 设定与用户已锁定剧情冲突；
- 章纲没有目标章，且补纲会改变结局或重大人物命运；
- 连续三轮钩子仍越界，或修订会删除超过 10% 正文；
- 外部检测需要把正文发送出本机但用户没有明确同意；
- 更新包版本低于本地版本、包校验失败或替换失败。

停下不是失败：保留已生成的草稿和报告，明确下一步需要用户确认的一个问题。更多恢复路径见[常见问题](常见问题.md)。
