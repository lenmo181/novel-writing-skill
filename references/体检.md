# 体检手册（设定库与连续性健康检查）

> 触发：`体检 / 健康检查 / 设定库诊断 / 连续性体检 / 这书是不是有硬伤 / 大纲和档案对不对得上`。
> 与 `审校.md` 的分工：**审校**针对**单章**（对抗式审查、追读诊断、过审校对）；**体检**针对**全书档案层**（大纲 / mind / 设定的一致性与完整性）。写完一章用审校，写了几十章或接手旧书用体检。
> 配套脚本：`tools/grep_consistency.py`（四类硬矛盾告警，含D类推进力打圈）、`tools/check_refs.py`（技能包引用完整性）。

---

## 一、体检对象

| 层 | 文件 | 体检什么 |
|----|------|---------|
| 世界基石 | `设定/世界观.md`、`设定/角色.md`、`设定/金手指.md`、`设定/文风样本.md` | 三根高压线是否被正文违反、角色烙印是否漂移、金手指是否越界、文风样本是否齐备 |
| 大纲 | `大纲/总纲.md`、`卷纲.md`、`章纲.md`、`场景纲.md` | 四级大纲是否齐备、里程碑是否落位、章纲字段是否完整（含节奏类型）、结局要素是否可倒推 |
| 档案 | `mind/` 七档案 + `mind/回顾/` | 角色状态链、伏笔生命周期、时间线、章节目录连续性、锚点日志、走向锁定、作者记忆 |

## 二、扫描项（逐项过，不留空）

| 编号 | 扫描项 | 数据来源 | 判读口径 |
|------|--------|---------|---------|
| S1 | **目录连续性** | `mind/章节目录.md` + `书稿/` 实际文件 | 章号连续无跳号无重复；目录条目数 = 实际章节文件数；末行进度行与最新章一致 |
| S2 | **缓冲比** | 章纲「节奏类型」列 | 缓冲类（对话/线索/代价）+ 校准占比 vs 基准 25%（20+5）；**软指标，只提示不判失败**；同时检查硬下限：任意连续 2 章是否有爽点或期待线推进 |
| S3 | **伏笔生命周期与沉睡** | `mind/伏笔追踪表.md` | 每条伏笔有 Tier；超沉睡阈值未推进（T3 15-20 / T2 30-40 / T1 卷末审计）→ 告警；回收率（核心 ≥80% / 跨卷 ≥60%）低于目标 → 提示 |
| S4 | **角色状态链** | `mind/角色状态快照.md` + 正文 | 位置/持有/状态/情绪/知情/最后出场 六栏是否逐章更新；已退场角色是否再出场；状态是否与最近章正文冲突；别名与首次出场章是否登记 |
| S5 | **时间线与实体** | `mind/时间线.md` + 正文 | 故事内时间推进无倒挂无跳漏；同一物品是否存在双持有人；同一实体是否有两种叫法未归一 |
| S6 | **因果与代价** | 章纲 + 正文 + `mind/回顾/` | 重大事件是否有前置因果链；重大增益是否在 1-5 章内有对应代价 |
| S7 | **文风样本完备性** | `设定/文风样本.md` | 有/无；有则检查四栏（风格定位/样本文本/风格基因/反例黑名单）是否填全 |
| S8 | **剧情推进力（v7.9 反打圈）** | `mind/章节目录.md` 节奏类型列 + 章纲 + 最近正文 | 机械层：`grep_consistency.py` D 类（同节奏类型连续 ≥3 章 / 缓冲型合计连续 ≥4 章）；语义层：最近 5-10 章是否同一矛盾连续 ≥2 章未推进、同一冲突模式 ≥3 次未变奏（对照 SKILL《剧情推进力铁律》打圈黑名单） |

**脚本可代跑的部分**：S1 的连续性（`gen_index.py` 重生成对比）、S4/S5 的 A/B/C 三类硬矛盾与 S8 的 D 类（`grep_consistency.py` 四类）；其余为 AI 语义判读。

## 三、报告结构（固定四段）

### 第一段：总体结论（6 行表）

| 项目 | 结论 |
|------|------|
| 体检范围 | 第 X-Y 章 / 全书（截至第 X 章） |
| 总体结论 | 健康 / 需关注 / 存在阻塞项 |
| 高风险项 | N 项 |
| 中风险项 | N 项 |
| 低风险项 | N 项 |
| 是否阻塞续写 | 是 / 否（阻塞项只作告警与建议，见 §5） |

### 第二段：问题清单表

| 编号 | 风险级别 | 位置 | 问题 | 影响 | 建议修复 |
|------|---------|------|------|------|---------|
| HC-001 | 高 | mind/伏笔追踪表.md 第12行 | T2 伏笔「玉佩来历」已沉睡 46 章（阈值 30-40） | 读者已遗忘，回收时无爽感 | 在下一章插入 3-5 行回扣，或降级为 T3 并就近回收 |
| HC-002 | 中 | 大纲/章纲.md 第88章 | 节奏类型为空 | 无法校验峰值间距 | 补标节奏类型 |

编号规则：`HC-三位序号`，一次体检内序号连续，便于用户指名讨论。

### 第三段：阻塞项

列出"必须先修才能继续写"的问题（如：章纲缺当前卷后续 10 章、角色状态快照停在 30 章前、走向锁定与正文冲突未裁定）。

### 第四段：建议执行指令

给出用户可直接复制的指令，如：

```
回填大纲 第60-70章
补纲 第71-80章
初始化续写
```

## 四、风险分级口径

| 级别 | 判定标准 | 处理时机 |
|------|---------|---------|
| **高** | 会导致吃书/读者可见硬伤/无法续写（如角色已亡又出场、时间线倒挂、章纲缺失、正文违反高压线） | **必须先修**，修完再写下一章 |
| **中** | 影响质量但不致命（伏笔沉睡、缓冲比偏高、状态快照滞后 3-5 章、文风样本缺失） | **建议修**，可在下一个缓冲章顺带处理 |
| **低** | 可延后的整洁性问题（别名未归一、章节目录日期缺失、锚点日志格式不一） | **存档时修**，卷末集中清理 |

---

## 五、阻塞项处理原则（只告警，不强锁）

- 体检发现的**阻塞项只作告警与建议，不做硬锁**：不阻止用户继续写，不自动改写任何档案。
- 理由：体检是**诊断**不是**裁决**；作者可能有意为之（如故意让"已亡"角色以幻觉/替身/回忆形式出场），机器不应越权判定。
- 所有修复动作由用户确认后执行；用户要跳过阻塞项直接续写，照做，但需在报告中留一行"已告知风险"。
- **不得**采用"销毁整批重写"的处置方式——本技能是逐章流式写作，任何问题都**就地修复**。

## 六、数据源边界声明

- **未提供的文件不推断**。项目里不存在 `设定/文风样本.md`，则 S7 记"未配置"，不推断文风；不存在 `mind/时间线.md`，则 S5 记"该档案缺失"，不凭正文猜测时间线。
- 档案缺失本身算问题（高或中风险，视档案重要性），但**不得用编造内容填空**；缺失项一律标 `[待补充]`。
- 体检报告只读不写：不修改任何档案文件，除非用户对某条建议明确说"修"。
