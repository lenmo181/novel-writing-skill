# 工具选择与最短路径（v7.39）

第一次使用只需要先记住一条：**开新书用 init_project.py，写章节用 check_chapter.py，查项目用 project_health.py，查技能包用 doctor.py，准备发布用 release_check.py。** 其他工具按问题出现时再调用。

## 先按问题选工具

| 你要解决的问题 | 首选工具 | 它负责什么 | 不负责什么 |
|---|---|---|---|
| 章节能不能交付 | `tools/chapter_readiness.py` | 工程 Gate；正式交付可追加第14-30项语义证据与全文 strict | 语义 Gate 只验证证据记录，不替作者做文学判断 |
| 只看 AI 味初筛 | `tools/check_chapter.py --ai-lite` | 零依赖输出本地启发式分数与触发指标 | 不等同于第三方模型结论 |
| 技能包装没装好 | `tools/doctor.py` | 目录、版本、语法、引用和入口冒烟 | 不读取小说项目，不修正文 |
| 技能包准备发布 | `tools/release_check.py` | 发布前集中预检、测试、安装副本比对 | 不代替日常自检 |
| 创建新书骨架 | `tools/init_project.py` | 创建目录、四级大纲、七档案和审校断点；默认不覆盖 | 不替作者决定剧情，不初始化短篇模式 |
| 开写前/交接总检查 | `tools/project_health.py` | 汇总结构、连续性、实体台账、待补充字段和审校待办 | 不修改正文或档案 |
| 全书问题分级+修稿队列 | `tools/full_review.py` | P0-P3 分级、五类问题、修复队列（断档/复活/换皮/节奏连续），报告落盘 | 不修改任何文件；不替代单章审校（单章问题仍走审校/去AI味） |
| 项目目录是否完整 | `tools/project_audit.py` | 章节编号、目录进度、剧本覆盖和骨架 | 不判断文学质量 |
| 档案是否前后一致 | `tools/continuity_check.py` | 角色、伏笔、时间线、标题和回顾覆盖 | 不自动改剧情 |
| 角色关系与出场台账 | `tools/entity_index.py` | 读取角色档案中的姓名/别名/关系，统计实际出场并输出 Mermaid 关系图 | 不从正文自动创造新角色 |
| 研究来源台账可不可信 | `tools/research_audit.py` | 检查台账字段、重复编号、异常状态和本地路径可解析性 | 不联网核实，不判断来源内容真伪 |
| 是否存在硬矛盾/打圈 | `tools/grep_consistency.py` | 已亡复活、伤势、物品归属、推进力打圈告警 | 不替代连续性报告 |
| 改稿到底改了什么 | `tools/chapter_diff.py` | 字数、对话比例、删除比例和差异 | 不判断改稿是否更好 |
| 本章结构和留存风险 | `tools/retention_check.py` | 信息增量、跨章重复、章末形态建议 | 只做建议级分析 |
| 朱雀线上检测 | `tools/zhuque_check.py` | 外部定量复核和高风险分段定位 | 需要明确同意发送正文 |
| 墨尺本地检测 | `tools/mochi_check.py` | 本地服务的细分指标和全书报告 | 需要先有墨尺服务 |

## 三条最短命令

```powershell
# 1) 安装后只做一次：检查技能包
python tools/doctor.py

# 2) 写完一章：检查章节硬卡
python tools/check_chapter.py "书稿/第001章_章节名.md"

# 3) 没有墨尺或不想下载外部包：做免依赖 AI 味初筛
python tools/check_chapter.py "书稿/第001章_章节名.md" --ai-lite

# 4) 新书或旧项目接手：先看项目总体健康
python tools/project_health.py "<项目根>"
```

## 新书最短路径

```powershell
python tools/init_project.py "<项目根>" --title "雾城拾荒者" --genre "都市悬疑" --platform "番茄" --target-words "80万字"
python tools/project_health.py "<项目根>"
python tools/entity_index.py "<项目根>" --out "<项目根>/mind/实体索引.md"
```

`init_project.py` 只补缺失文件；已有正文、档案和同名文件均保留。短篇使用 `references/短篇模式.md` 的单文件结构，不调用这个长篇脚手架。

## 自检工具为什么看起来重复？

- `doctor.py` 是**总入口**：适合“技能找不到/安装后先查一次”。
- `lint_skill.py` 是**规则漂移检查**：适合改过版本、默认值或文档后核对。
- `check_refs.py` 是**悬空引用检查**：适合新增或重命名手册后核对链接。
- `release_check.py` 是**发布门**：适合打包前一次性汇总，不是日常写作必跑。

因此日常不需要四个都跑：**新书先 `init_project.py`，已有项目先 `project_health.py`；只有报告提示具体类别时，再补对应工具。**

## AI 检测的降级链

1. 默认：本地 `check_chapter.py`，零下载、零联网，输出 AI 味粗测和触发指标。
2. 需要更细指标：安装墨尺后运行 `mochi_check.py`，正文不离开本机。
3. 需要外部定量复核：明确同意后运行 `zhuque_check.py --allow-external`。

外部检测未配置、下载失败或服务不可用时，仍可完成前两级，不阻塞普通写作；回执中标明“未完成哪一级检测”即可。
