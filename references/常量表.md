## 六、AI味检测（朱雀线上 + 墨尺本地）

**通路选择**：优先朱雀（线上模型判定，需额度）；**朱雀额度用尽或离线 → 墨尺本地兜底**（零额度零依赖）；`check_chapter.py` AI味指数（机械粗测）始终在。
**统一交付线（v7.8 定名，v7.25 复核口径）：百分制「人类分」≥90 达标；<80 硬卡禁止交付；80-89 警告过闸但须逐段过目**。人类分口径：朱雀=人工占比×100；墨尺=total×10。分数越高越好（朱雀 AI%／AI味指数为反向指标）。

## 八、修改约定（改数值前必读）

| 档 | 参数 | 要求 |
|----|------|------|
| ① **可直接改** | 字数区间、对话占比、宏观节奏比例、缓冲比、沉睡阈值、回收率、章节名长度（2-12）、文字墙阈值（WALL_*）、全文审稿阈值（FULL_REVIEW_*） | 改完按下方「改后必做」执行；墙/审稿参数改的是 `config.py`，常量表·二/十三须同步 |
| ② **改后必须同步脚本** | 单章字数（默认值）、对话占比、朱雀/墨尺阈值、章节名长度/黑名单 | 先改 `tools/config.py`，再运行 `python tools/lint_skill.py` 与回归测试；脚本不得各自复制默认值 |
| ③ **严禁改** | 爽点间隔硬下限（≤3 章）、平台审核红线（见 SKILL.md《平台审核红线》） | 这两项是交付底线，任何情况下不得放宽 |

**改后必做（三步，缺一不可）**：
1. 重跑一次相关校验：`python tools/check_chapter.py "<章节文件路径>"`（字数/对话改动）；`python tools/conflict_score.py --demo`（冲突值改动）；
2. 在 SKILL.md「版本历史」追加变更说明（日期 + 改了哪个数值 + 从多少到多少）；
3. 若该数值出现在各手册正文中，同步修订手册表述，避免表内表外两套数。

**版本日志四段式（v7.34 起发版强制，用户裁定 2026-09-30）**：每次版本历史的条目必须分四类描述清楚，缺一类写「无」——
1. **更新了什么**（新增能力/工具/手册/参数）；
2. **修复了什么**（Bug、口径漂移、误伤，写明旧错→新对）；
3. **降级/删除了什么**（硬卡降警告、废除规则，含原因）；
4. **验证证据**（测试数变化、lint/doctor/实测结论）。
禁止只写「优化了体验」「技能已升级」这类无信息量表述；提交信息与 README 摘要同口径。
