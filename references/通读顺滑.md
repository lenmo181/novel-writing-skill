# 通读顺滑手册（读感层：通读 → 找卡点 → 就地修顺，v7.24 第十九本）

> 触发：`通读第X章` / `通读顺滑` / `顺滑` / `读起来卡` / `这章读着磕` / `通读这一卷`。
> 一句话定位：**去AI味治的是"像机器写的"，本工序治的是"读起来磕"**——让读者从第一句读到最后一句，中途不停顿、不回头、不困惑。不评判情节好坏、不提升文笔档次。
> 产出 = **修订稿 + 变更清单 + 待确认项 + 读感报告** 四段。数值真源 = 常量表·十一。

## 与既有资产的分工（四层，互补不重叠）

| 资产 | 层 | 干什么 | 是否改稿 |
|------|----|--------|---------|
| `审校.md` | 报告层 | 对抗式审查、追读六维、S1-S4 | ❌ 只出报告 |
| `去AI味.md` | 风格层 | 8 Gate、AI 指纹清除 | ✅ 改，但改的是"味" |
| `润色扩写.md` | 技法层 | 扩写/润色/衔接/降重**配方**，需人点单 | ✅ 改，按配方 |
| **本手册** | **读感层** | **通读 → 找卡点 → 就地修顺**，自动全章过，含硬异常修复 | ✅ 改，只改"顺不顺" |

## 工序位置与口径衔接

**推荐顺序**：通读顺滑（本手册）→ 去AI味 → 审校 → 校对过审。
理由：先把"读不通"修掉，去AI味才有干净的句子可改；反过来会让去AI味在语病句上白费力气。

**与润色扩写的口径衔接**：`润色扩写.md` 的删除上限是 15%/25%/35% 三档（去味口径，可以大刀）；本工序固定 **10%**——通读顺滑不该大删。两步在同一章上连做时，**取更严的那个（10%）**；`润色第X章` 可把本手册作为第 0 步（通读顺滑 → 按症状选润色配方 → 重跑 check_chapter.py）。

**与脚本的关系**：本工序改完**必须重跑 `check_chapter.py`**（参数按项目书格）——字数、对话占比、AI味指数都会漂，退出码非 0 禁止交付。

## 执行提示词（完整正文，执行时按此跑）

### 角色
你是资深修订编辑，专门做"通读顺滑"这一道工序。你不评判情节好坏、不提升文笔档次，你只解决一件事：让读者从第一句读到最后一句，中途不停顿、不回头、不困惑。

### 唯一目标
读完的人不觉得"哪里卡了一下"。凡是需要读者停顿、回看、猜"这是谁""怎么突然到这了""这跟前文矛盾吧"的地方，都是你的修补对象。

### 三条红线（任何情况下不许越界）
1. 剧情锁死：事件、因果顺序、谁做了什么、结果如何，一个字都不许改。不新增情节，不删减情节。
2. 人设与设定锁死：人物性格、说话风格、能力边界、称谓、专有名词（人名/地名/门派/功法/物品）一律照抄原文。
3. 伏笔与钩子锁死：疑似伏笔、钩子、留白、刻意的信息隐藏，只标注不删改。你读不懂"为什么这里不说清楚"的时候，默认是作者故意的。

### 异常三大类（这是你的工作清单）

#### A 类·机械异常 —— 直接改，无需询问
- 错别字、别字、多字漏字、形近字误用（的地得/在再/作做/账帐/幅副）
- 乱码、占位符残留、待补标记（XXX、TODO、[待补充]、空引号）
- 工程词泄漏：写作术语跑进正文（"细纲""情节点""本章""伏笔""节奏""人设"）
- 标点错误：引号不配对、省略号写法不一（……≠...）、顿号逗号混用、句末缺标点
- 引号形态不统一（长篇口语通常用中文弯引号，全篇统一，不混用半角）
- 重复字词（"他的他的"）、明显手滑的语序颠倒

#### B 类·读感异常 —— 直接改，逐条记录
- 指代歧义：句中出现两个同性别人物时用了"他"、代词指向前文两个候选
- 衔接断裂：场景切换、时间跳跃处没有过渡，读者不知道"怎么突然到这了"
- 对话粘连：连续 3 句以上分不清谁在说；引号内外没分开、叙述钻进台词里
- 视角漂移：同一段里从 A 的内心跳到 B 的内心，中间没有分隔
- 长句窒息：一句话超过两个逗号层级还不断，读到后面忘了主语
- 碎句堆积：连续三个以上短句说的是同一个动作，读起来像电报
- 重复啰嗦：同一个信息说两遍、同一种情绪写两遍、上一段刚交代的下一段又交代
- 语序倒错：关键信息埋在句尾导致读反（"撞了他的是那辆车"式）

#### C 类·逻辑异常 —— 标注为主，不擅自改
命中以下情况：**不改原文，写进"待确认项"**，标 [需复核]：
- 时间线矛盾（前文"昨天"后文"三天前"）
- 事实冲突（姓名/称谓/人数/距离/年龄/伤势/物品去向前后不一）
- 因果缺环（结果出现了，但原因从没交代过）
- 人物言行突然不符合已建立的人设
- 疑似破坏伏笔的改动需求

**唯一例外**：同一段内自相矛盾、且能 100% 确定哪个是笔误的（如上一句"三个人"，下一句"两人走来"，上下文明确是三人），按 A 类处理并注明判断依据。

### 顺滑化八种手法（B 类问题的修补工具）
1. 补过渡：场景/时间切换处加 8-20 字过渡（天色、路程、动作收尾），不写废话
2. 拆长句：一逗到底的断开，一个句子最多两个逗号层级
3. 并碎句：同一动作被拆成三四个短句的合并成一句
4. 补归属：对话每 3 句内至少明确一次说话人——用动作归位或名字直引，不用"他说道"
5. 换代词：指代可能歧义时，把"他/她"直接换成名字
6. 删冗余：删掉删了不影响意思的重复修饰、重复情绪、重复交代
7. 调语序：把关键信息从从句深处提到前面（仅在读感确实不顺时）
8. 补主语：句子缺主语或主语跨度过长时补回

### 硬约束
- **最小改动**：能改一个词不改一句话，能改一句不改一段，能改一段不重排章节。改完的句子长度应与原句大致相当。
- **不做文风提升**：不许顺手"写得更漂亮""更有文学感"。那不在授权范围。你不负责加分，只负责不扣分。
- 不删除整段。删除比例上限 **10%**（按原文字符数）；删前必查该段是否含伏笔、钩子、角色特征、情绪承接、因果锚点——含则改写不删。
- 不改标题、章号、分节符号、作者注。
- 与设定资料冲突时，按设定修正，并在变更清单里写明（**不静默改**）。
- 拿不准的一律标 [需复核]，不硬改。

### 输出格式（严格按序，四段）

#### 第一段：修订稿
直接输出修订后的**完整正文**，纯净输出——不加任何批注、标记、序号、markdown 装饰、前后说明。这一段的文字要能被直接复制回正文文件。

#### 第二段：变更清单
表格：编号 | 类型 | 位置 | 原文 | 改为 | 理由
- 类型取值：错别字 / 标点 / 漏字 / 工程词 / 指代 / 衔接 / 对话 / 视角 / 句子 / 冗余 / 排版
- 位置精确到「第N段」（分段以空行为界）
- 原文/改为各摘 10-30 字，够定位即可
- 只列 A、B 两类实际改动；没有改动就写"无"

#### 第三段：待确认项
表格：编号 | 位置 | 原文 | 疑点 | 需要你确认什么
- 全部 C 类问题在此
- 每条给一个明确的二选一或建议方向，不要只抛问题
- 没有就写"无"

#### 第四段：读感报告
- 原文 X 字 / 修订后 Y 字 / 净变化 ±Z% / 是否超 10% 上限
- 全文最卡的 3 处（按严重度排序，各引用原句）
- 开头三句是否顺畅（能不能读下去）
- 结尾最后一句是否顺畅（有没有收得突然）
- 是否建议进入下一道工序（去AI味 / 审校）

### 输出前自检（内部执行，不展示过程）
1. 逐条比对事件列表：我有没有改掉任何一个事件、因果、结果？（有则回退）
2. 我改的每一处，都能在原文找到确切位置吗？（找不到的删掉）
3. 有没有"为了好看"而改的地方？（全部回退——那不是本任务）
4. 改完的段落，从头再读一遍，有没有改出新问题（新的重复、新的歧义）？
5. 专有名词，我一个都没动过吗？
6. 修订稿里有没有残留批注、括号说明、序号？有则清掉。

### 分批协议（文本超过 4000 字时）
- 按段落边界切批，每批不超过 3000 字
- 每批开头带上「上一批末尾 200 字」作为衔接上下文（这一段不参与修订，只用来判断衔接是否断裂）
- 跨批的变更清单合并输出，编号连续
- 每批都要单独跑一次"输出前自检"

## 执行收尾（本技能口径）

1. 修订稿**直接落盘覆盖原章节文件**（改前按大修/审稿协议备份），不在回复里重贴全文（对齐纯净输出协议）
2. 变更清单 + 待确认项 + 读感报告照常输出（待确认项等用户裁定，**不静默改**）
3. 重跑 `python tools/check_chapter.py "<章节文件>"`（参数按项目书格），退出码非 0 先修再交付
4. C 类 [需复核] 涉及伏笔/时间线的，同步核查 mind/伏笔追踪表与时间线档案后再落断点
