# 云盘备份手册（v7.14）

> 把写作成果**镜像同步**到**中国移动云盘**，防本地磁盘故障、误删、勒索加密丢稿。核心工具 `tools/cloud_sync.py`：本地目录与云盘 `小说备份/<书名>/` **逐文件直传、目录结构 1:1**，不打包 zip。上传通路走官方「中国移动云盘Skill」（**cm-cloud-manage**，skillhub/技能市场安装）。

## 一、触发时机与指令

| 触发 | 时机 | 行为 |
|------|------|------|
| **自动·章同步** | 写章流程**第五步**完成后 | `python tools/cloud_sync.py "<项目根>"`（增量，秒级） |
| **手动·全量** | 用户说 `备份` / `同步云盘` / `上传云盘` / `移动云盘备份` | 同上（全量对比一遍，无变化秒完成） |

## 二、同步协议

- **目录映射**：本地 `<项目根>/` ↔ 云盘 `/AI空间/智能体云盘助手/小说备份/<书名>/`，子目录（书稿/、mind/、大纲/、设定/…）1:1。
- **增量判据**：云盘同名文件存在且**字节数相同** → 跳过；不存在或大小不同 → 上传（`--force` 强制全传）。
- **排除**：`out/`、`.git/`、`__pycache__/`、`*.tmp/.temp/.lock`。
- **回收站约定（重点）**：移动云盘 API **无删除、无覆盖**——同名上传时旧版会被云端自动改名留档。本脚本在上传新版前，先把云端旧版改名为 **`【旧】原名`**（update 接口），再让新文件占用原名。因此：
  - **原名文件 = 永远最新版**（一致性保证）
  - **带 `【旧】` 前缀的 = 垃圾**，客户端搜索「【旧】」可批量找到，**用户定期手动删除**即可（脚本不删、云端也删不了）
- 退出码：0=成功（含全跳过）；1=有失败文件；2=技能未安装/未授权。`--dry-run` 只对比不传。

## 三、执行方式

1. 同步脚本自动定位 `~/.zcode/skills/cm-cloud-manage/`（或 `@org-vt43r0t0/` 嵌套目录），导入其 Python 模块直接调用，不走逐条 CLI。
2. 首次使用先完成**账号登录授权**（技能 `login` 子命令 → 把 loginUrl 发给用户点击；token 失效时重跑 login 重发）。
3. 上传完成后脚本输出同步报告（新建/更新/跳过/失败），AI 把摘要行转述给用户：`☁ 已同步：新建X 更新Y 跳过Z → 移动云盘`。

## 四、降级与失败处理（铁律：备份永不阻塞写作）

| 情况 | 行为 |
|------|------|
| 技能未安装 | **跳过不阻塞**：留一行「移动云盘技能未安装，本次备份跳过（skillhub install @org-vt43r0t0/cm-cloud-manage --dir ~/.zcode/skills 安装后自动生效）」，写作流程照常 |
| 未登录授权/token 失效 | 退出码 2：执行 `login` 把授权链接发给用户，**本次会话不再重复询问**，下次会话再试 |
| 单文件上传失败 | 脚本重试后仍失败则记入失败清单（`x` 行），整体退出码 1；写作流程继续，断点记录追加「云盘同步失败@第X章」 |
| 服务端"缓存信息失效" | 脚本已内置退避重试（3 次递增间隔）；仍失败多为新建目录索引延迟，隔一会儿重跑即可 |

**分级口径**：备份是**软门禁**（同文风样本、朱雀未配 Key 口径）——失败不判写作失败、不禁交付，但**必须可见**（留痕），禁止静默跳过。

## 五、整书快照（可选，仅完结）

平时**不打包 zip**（用户明确要求直传镜像）。仅在**全书完结**时可选打一个全量 zip 存到 `小说备份/<书名>/快照/`（命名 `<书名>_YYYYMMDD_HHMM.zip`，排除 out/、.git、*.tmp），作为终版存档。日常历史版本靠 `【旧】` 留档 + 本地 git。

## 六、验收标准

- **一致性**：同步后重跑脚本 → 应 `跳过=全部、失败0`（幂等）。
- **更新**：改一个文件再同步 → 该文件显示 `~` 更新，云端出现 `【旧】原名`，原名内容为新版。
- **降级**：技能未安装时，写章流程完整走完且回复含跳过提示行（不报错、不卡住）。

## 七、与其他机制的关系

- 与跨会话续跑协议互补：断点记录管"下次从哪写"，云盘镜像管"另一台机器/恢复场景有全量数据"。
- 本地项目永远是真源；**禁止**从云盘反向覆盖本地（用户明示本地已损坏要恢复除外）。
- mind/ 档案每章都会变 → 每章产生一个 `【旧】` 留档属正常现象，攒多了在客户端批量清理。
