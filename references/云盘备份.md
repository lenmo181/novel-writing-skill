# 云盘备份手册（v7.13）

> 把写作成果自动备份到**中国移动云盘**，防本地磁盘故障、误删、勒索加密丢稿。上传动作走官方「中国移动云盘 Skill」（**cm-cloud-manage**，ZCode 技能市场安装，中移互联网出品）；本手册只定义**什么时候备份、备份什么、传到哪、失败怎么办**，上传接口以对方技能自己的 SKILL.md 为准——本技能不复制、不假设其内部实现。

## 一、触发时机

| 触发 | 时机 | 备份内容 |
|------|------|---------|
| **自动·章备份** | 写章流程**第五步**（更新档案）完成后 | 本章正文 + `mind/` 全部档案 + 最新断点 |
| **自动·里程碑** | 卷末章 / 完结章落盘后 | 整书 zip 快照 |
| **手动·全量** | 用户说 `备份` / `云盘备份` / `上传云盘` | 整书 zip 快照（当前项目） |

## 二、云盘目录结构（约定）

```
小说备份/
└── <书名>/
    ├── 书稿/第XXX章_章节名.md      # 章备份：逐章覆盖式同步（同名覆盖）
    ├── mind/…                      # 档案：与本地 mind/ 结构一致
    └── 快照/<书名>_YYYYMMDD_HHMM.zip  # 全量快照：时间戳命名，只增不覆盖
```

- 章备份是**镜像同步**（云盘=本地当前态）；快照是**存档**（历史不可变）。丢稿兜底靠快照，日常恢复靠镜像。
- 快照打包**排除**：`out/`、`*.tmp`、看板中间产物等临时文件（保留 `看板.html`，它本身是单文件离线页）。

## 三、执行方式（调用 cm-cloud-manage）

1. **可用性检测**：cm-cloud-manage 是否在当前会话可用技能列表中。
2. **可用 →** 按其 SKILL.md 执行：首次使用先完成**账号登录授权**（需用户扫码/确认，提示一次即可，不要每章重复问），之后调用其**上传**能力按第二节目录结构落盘；上传完成后**列目录核验**目标文件存在，才算备份成功。
3. **手动快照**：先在本地打包 zip（`python` 标准库 `zipfile` 或等价方式，文件名见第二节），再上传，核验后删除本地临时 zip。
4. 每次备份成功在回复末尾留一行：`☁ 已备份：<内容摘要> → 移动云盘`。

## 四、降级与失败处理（铁律：备份永不阻塞写作）

| 情况 | 行为 |
|------|------|
| 技能未安装 | **跳过不阻塞**：跳过备份，过程回复留一行「移动云盘技能未安装，本次备份跳过（ZCode 技能市场搜 cm-cloud-manage 安装后自动生效）」，写作流程照常继续 |
| 首次授权被跳过/失败 | **跳过不阻塞**；**本次会话不再重复询问**，下次会话再试 |
| 上传失败（网络/服务端） | 重试 **1 次** → 仍失败则断点记录追加「云盘备份失败@第X章」，继续写作，不重试更多 |
| 单文件过大/超时 | 放弃该文件并在备份行标注，不影响其余文件 |

**分级口径**：备份是**软门禁**（同文风样本、朱雀未配 Key 口径）——失败不判写作失败、不禁交付，但**必须可见**（留痕），禁止静默跳过。

## 五、验收标准

- **章备份**：云盘端能列出本章文件，且内容与本地一致（按对方技能的查询/下载能力抽查字数或大小）。
- **快照**：zip 在云盘端存在、命名含时间戳；本地解压抽查含 `书稿/` 与 `mind/`。
- **降级**：技能未安装时，写章流程完整走完且回复含跳过提示行（不报错、不卡住）。

## 六、与其他机制的关系

- 与跨会话续跑协议互补：断点记录管"下次从哪写"，云盘快照管"历史任何一版都在"。
- 卷末/完结的里程碑快照**不替代**手动备份；完结前建议手动再打一次全量快照。
- 本地 `mind/` 永远是真源，云盘只是副本；**禁止**从云盘反向覆盖本地（除非用户明示本地已损坏要恢复）。
