# 操作范例与产出契约（v7.36）

这份手册把常见请求压缩成可复制的输入、可见动作和验收结果。第一次使用先看[快速开始](快速开始.md)，工具职责看[工具选择](工具选择.md)。统一回执字段的完整定义见[回执协议](回执协议.md)；本手册不是新的规则真源，数值与硬卡仍以 `SKILL.md`、`references/常量表.md` 和对应脚本为准。

## 一、统一回执契约

每个主流程完成后，回复至少包含四项：

1. **状态**：已完成 / 暂不交付 / 仅生成草稿 / 等待确认。
2. **实际变更**：列出新增或修改的文件；只读流程明确写“未修改项目文件”。
3. **校验证据**：脚本名、退出码、报告路径或待确认项；不能只写“已检查”。
4. **下一步**：下一章、待用户裁定的一个问题，或明确的恢复命令。

交付前至少能回答：改了什么、为什么合格、还有什么没做。外部服务未授权、网络失败和未配置 Key 必须显式标记，不得写成“通过”。

## 二、四条高频端到端范例

### 范例 A：新书到第一章

用户输入：

```text
初始化项目，书名《雾城拾荒者》，都市悬疑，预计80万字。
确认大纲后写第1章，标准级，章末留下悬念钩子。
```

最小动作链：

1. 建项目骨架和草案；重大设定标 `[待确认]`，停在确认点。
2. 用户确认后读取第1章章纲、角色状态、时间线和最近回顾。
3. 建约束锁，写正文，按实际章末钩子命名章节。
4. 跑 `check_chapter.py`，做 30 项语义复核；硬伤就地修复并重验。
5. 更新章节目录、直接依赖档案和单章回顾，再回报断点。

合格回执：

```text
状态：已完成第1章《停在2317》
变更：书稿/第001章_停在2317.md；mind/章节目录.md；mind/回顾/第001章回顾.md
校验：check_chapter.py 退出码 0；30 项语义复核完成；无未标记外部检测
下一步：【断点】下一章第2章；待办：确认怀表遗言的第二个信息点
```

### 范例 B：接手旧稿后续写

用户输入：

```text
导入旧稿：D:\小说\雾城拾荒者，保留原设定，接着写第42章。
```

适配动作：先跑 `project_audit.py`，再按《导入旧书》映射到 `mind/`；已有正文只读，缺项写 `[待补充]`，不凭空补设定。映射完成并确认断点后，再用 `context_pack.py --chapter 42` 生成来源可追溯上下文包，最后进入标准级写章。

## 2. 角色关系与交接

用户输入：整理角色别名、关系和每个人最近出场章。

适配动作：新书先运行 `init_project.py` 建骨架，再运行 `project_health.py` 暴露待补充字段；旧书先跑 `project_audit.py`，再按《导入旧书》映射到 `mind/`。已有正文只读，缺项写“[待补充]”，不凭空补设定。运行 `entity_index.py <项目根> --out <项目根>/mind/实体索引.md` 检查别名冲突、零出场实体和关系图，再由作者确认后写回角色档案；交接时追加 `project_health.py <项目根> --out <项目根>/mind/项目健康报告.md`。

停靠点：如果章纲没有第42章，先报告缺口并给“补纲 / 换章号 / 仅写草稿”三个选项，不直接改结局。

### 范例 C：只审不改与审后修复

用户输入：

```text
审校第12章，只看节奏、逻辑和人物行为，不要改正文。
```

只读输出：按《审校.md》给问题位置、证据、严重度和建议，不落盘修改。

用户随后输入：

```text
按刚才的问题修复第12章，保留伏笔和章末钩子。
```

执行前先 `snapshot_project.py`，修复后跑 `chapter_diff.py` 和 `check_chapter.py`；删除比例超过 10% 或触碰钩子/因果/人物状态时，停在待确认点，不静默归档。

### 范例 D：技能自检与更新

用户输入：

```text
技能好像找不到，先自检；如果有新版本只告诉我，不要更新。
```

先运行：

```powershell
python tools/doctor.py
python tools/update_skill.py --check --json
```

前者只读检查本地包；后者只检查版本。只有用户明确说“更新/自动更新/升级”时，才进入备份、校验、替换和回滚流程；更新后仍显示旧内容，再重启 Codex 或重新加载技能列表。

## 三、三条专项请求

### 范例 E：没有外部检测服务，先做本地初筛

用户输入：

```text
先检查第12章有没有明显 AI 味，不上传正文，也不安装额外服务。
```

执行：

```powershell
python tools/check_chapter.py "书稿/第012章_章节名.md" --ai-lite
```

交付：输出本地启发式分数、句长/段长波动、比喻词和情绪词密度；这一步只做初筛，正式章节仍按完整 `check_chapter.py` 校验。

### 范例 F：把一章小说转换成剧本

用户输入：

```text
转剧本第12章，保留正文事件和章末钩子。
```

执行：读取第12章正文与最近回顾 → 转成 `剧本/第012章_章节名.md` → 检查场景、对白占比、心理残留和章末卡点。正文默认只读；剧本未过检时只修剧本病灶。

### 范例 G：准备发布技能包

用户输入：

```text
发布前检查技能包，只做本地检查，不上传。
```

执行：

```powershell
python tools/release_check.py --tests
```

交付：统一自检、评测矩阵、lint、引用检查、打包副本和回归测试结果；任何一项失败都列出具体修复入口。

## 四、按当前状态适配

| 当前状态 | 主入口 | 默认动作 | 禁止事项 |
|---|---|---|---|
| 没有项目 | `初始化项目` | 建骨架，生成草案，等待重大设定确认 | 未确认就写长篇正文 |
| 有规范项目 | `写第X章` / `续写` | 读取断点和最小上下文，标准级交付 | 扫全库、重写已完成章 |
| 有旧稿但无 mind/ | `导入旧书` / `初始化续写` | 只读盘点、映射档案、生成缺口清单 | 猜设定、覆盖旧正文 |
| 只有单个章节文件 | `快速级` 或 `审校` | 片段级检查和报告 | 假装已完成整章归档 |
| 需要外部检测 | `朱雀检测` / `封面` | 先说明数据是否离开本机，取得明确同意 | 未授权上传正文或提示词 |
| 技能包异常 | `自检技能` | `doctor.py` → `lint_skill.py` → `check_refs.py` | 反复改小说正文或删除档案 |

## 五、失败后的最短恢复

- **退出码 1**：正文质量硬伤；保留草稿，按报告定位，修复后重跑同一命令。
- **退出码 2**：路径/参数/输入错误；先修命令，不改正文。
- **退出码 3**：外部服务失败；标记“未检测”，继续本地流程或稍后重试。
- **会话中断**：只认已落盘且已校验的章节；先看 `mind/章节目录.md` 进度行，再说“续写”。
- **看板或可选产物失败**：记录失败原因，不阻塞已经通过基础闸门的正文交付。

## 五B、规则治理五范例（v7.35 新增）

**范例 1：全文审稿**
- 输入：`全文审稿 C:\...\我的书` 或 `python tools/full_review.py "<项目根>"`
- 动作链：结构扫描（断档/重复）→ 档案扫描（死亡复活/伏笔沉睡）→ 章节统计（字数偏离/换皮重复）→ 节奏连续 → P0-P3 分级排序
- 产物：mind/全文审稿报告.md（人读）+ mind/全文审稿队列.json（修复执行层消费）
- 回执：`P0×n P1×n P2×n P3×n`+队列路径；存在 P0 时明确「必须先修再续写」
- 停靠点：只诊断不修复；修复动作由用户确认后按队列逐条执行

**范例 2：修复队列消费**
- 输入：`修复 P0 问题` / `按队列修第3条`
- 动作链：读 mind/全文审稿队列.json → 用 `tools/repair_runner.py --list` 校验队列 → 按映射调专项修复器 → 修后用 `tools/repair_runner.py --mark-fixed <issue_id>` 登记 fixed
- 红线：**禁止整章重写**（forbidden_action 字段已注明）；每条修复范围不超过 repair_scope

**范例 3：二审**
- 输入：修完若干条后再次 `全文审稿`
- 动作链：自动读上轮队列 → 四分类对比（消失/保留/新增/回归）→ 仅已登记 fixed/auto_fixed 的历史位置才进入回归记忆
- 回执：`二审对比：消失 n｜保留 n｜新增 n｜回归 n`；回归>0 时逐条列出
- 完成定义：P0=0 且回归=0 才算治理收口

**范例 4：规则台账查询**
- 输入：`对话占比为什么是15-50` / `查 RB-006` / `哪些规则被废弃了`
- 动作链：查 references/规则台账.md 对应 RB 条目 → 回答来源轮次/验证计数/证据等级/状态/落点/执行工具
- 回执：一条规则的一生；质疑数值时走常量表「八、修改约定」，禁止只改台账

**范例 5：规则冲突处理**
- 输入：`SKILL 和常量表字数不一致` / 发现两处口径不同
- 动作链：以 tools/config.py 为程序真源、常量表为人读真源 → 定位漂移文件 → 统一口径 → 跑 `python tools/lint_skill.py` 验证 → 台账对应 RB 条目标「修正」并记变更
- 红线：发现 A=140/B=160/C=150 类冲突必须当场统一并留一行修正记录，禁止绕过

## 六、完成定义

标准级章节只有同时满足以下条件才算完成：

- 正文落盘，标题与实际章末钩子一致；
- `check_chapter.py` 退出码为 0；
- 30 项语义复核有证据，不只给结论；
- 直接依赖的 mind/ 档案与单章回顾已更新；
- 断点、待办和未执行的可选环节已明确回报。
