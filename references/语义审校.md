# 语义审校与第14-30项证据（v7.44）

> 目的：把第14-30项从“AI/作者口头判断”变成可复测的结构化证据记录。

## 输入

- 当前章节正文。
- 上一章正文、最近回顾、角色状态、时间线、伏笔表、章纲钩子。
- 项目级规则与题材/书格例外。

## 输出

保存到：`mind/审校/第XXX章审校.json`。

记录除了第14-30项外，还必须绑定当前章节的 `chapter_sha256` 和当前运行时 `version`。正文修改后旧证据自动失效，必须重新审校。\n\n每项必须至少包含：

```json
{
  "status": "pass|warn|revise|blocked",
  "evidence": "具体证据，而不是只写通过",
  "location": "第X段/第X场/第X句，可选",
  "confidence": 0.0
}
```

## 17项语义检查

| 项目 | 检查重点 | 失败处理 |
|---|---|---|
| 14 人设一致性 | 能力、决策、口吻、缺陷是否与角色档案一致 | 定位到具体行为/台词后修订 |
| 15 状态衔接 | 行为、因果、资源、身份、伤势、战力是否承接 | 对照上章与快照修复 |
| 16 逻辑漏洞 | 动机、因果、可滥用漏洞 | 标 evidence，必要时停在确认点 |
| 17 伏笔状态 | 应埋/推进/回收是否落到追踪表 | 更新追踪或标待定 |
| 18 时间线连续 | 时间顺序、跨度、场景时段 | 对照时间线修复 |
| 19 章末钩子 | DNA、归属、后果槽、章名三对齐 | 重构钩子后复测 |
| 20 对话质量 | 冲突、潜台词、信息差、归位变化 | 局部重写病灶段 |
| 21 活人感 | 自然度信号，不为过检强塞口头禅 | 允许 warn |
| 22 期待感 | 至少一条期待线被制造或推进 | 补目标/悬念/倒计时 |
| 23 视角纪律 | POV、信息权限、镜头越界 | 允许 warn，实质越界则 revise |
| 24 场景有效性 | 目标→阻碍→转折，删掉是否伤剧情 | 允许 warn |
| 25 信息增量 | 本章新信息是否足够且不过度解密 | 变量/线索重排 |
| 26 重复风险 | 与邻章的结构/表达是否换皮 | 结构变量注入 |
| 27 情绪兑现 | 章内情绪铺垫与兑现是否匹配 | 对落点做局部修复 |
| 28 钩子 DNA 与归属 | 章名、章纲、正文末钩子同源 | 重构后复测 |
| 29 因果与代价守恒 | 每个关键收益是否有合理代价/前因 | 修补因果链，不无中生有 |
| 30 剧情推进力 | 状态是否发生变化，是否原地打圈 | 换目标/限制/信息/代价 |

## 证据纪律

1. `pass` 必须有证据；不得只写“符合”。
2. `warn` 可以通过正式 Gate，但要保留人工过目理由。
3. `revise/blocked` 会让默认启用语义证据的 `chapter_readiness.py` 失败；`evidence` 必须是非空字符串。
4. 修复后必须重新生成记录；旧记录不得覆盖式删除，应由 Git/快照保留历史。
5. 本记录不等于文学质量评分；confidence 只是证据可信度，不是作品质量分。

## 弱证据档 weak（v7.44）

AI 语义复核不可用（离线、额度耗尽、模型拒答）时，第14-30项可以用**机械弱证据**兜底，
状态记为 `weak`，与「跳过语义检查」区分开：

| 档位 | 触发 | Gate 结果 | 能否当交付结论 |
|---|---|---|---|
| `pass/warn` | 正常语义审校 | ok | 可以 |
| `weak` | AI 不可用，只有机械证据 | ok，**不卡死** | **不可以**——`delivery_ready=false`，报告标 `semantic_strength=weak` |
| `revise/blocked` | 发现待修问题 | fail | 不可以 |
| `--skip-semantic` | 草稿自检 | ok | 不可以 |

纪律：`weak` 是「先放行、后补票」，不是「免检」。报告会列出具体哪几项是 weak
（`weak_checks`），AI 恢复后必须回填为 `pass/warn/revise` 再走正式交付。
**禁止把 `weak` 当作通过正式交付的常态路径**——连续 3 章以上 weak 应停下来安排语义审校。

## 推荐命令

```bash
python tools/review_skeleton.py "<项目根>" 42          # 生成第14-30项骨架（默认 revise，不会误通过）
python tools/review_skeleton.py "<项目根>" 42 --status weak   # 离线时直接生成弱证据档骨架
python tools/chapter_readiness.py "<项目根>" 42 --full --json
```

`review_skeleton.py` 的项名取自 `references/核心校验映射.md`（不另备清单），自动算好当前正文的
`chapter_sha256`；已存在记录时拒绝覆盖，`--force` 才覆盖。

草稿工程检查可显式添加 `--skip-semantic`（不可与 `--with-semantic` 同用）；此时 `ok` 仅表示工程检查通过，`delivery_ready=false`，不能作为正式交付凭据。`--full` 不写入全文审稿报告或队列。
