# 统一回执协议（v7.35）

> 版本：v7.34（规则治理与误伤清理版）｜数值真源：`tools/config.py`

所有主流程完成后都使用同一套回执字段。目的是让用户一眼看清：是否完成、改了什么、依据是什么、下一步做什么。

## 标准字段

```text
状态：已完成 / 暂不交付 / 仅生成草稿 / 等待确认 / 检测失败
主流程：本次只执行的主动作
实际变更：新增、修改或未修改的文件
校验证据：脚本、退出码、报告路径、复核结论
未执行项目：可选但未运行的工具、外部服务或后续动作
风险/待确认：会改变剧情、权限、外发数据或文件范围的事项
下一步：一个明确的后续动作或恢复命令
```

## 状态使用规则

| 状态 | 使用条件 | 不得写成 |
|---|---|---|
| 已完成 | 目标产物已落盘，必要检查已通过，直接依赖已更新 | 只生成了草稿或只给了建议 |
| 暂不交付 | 有硬伤、缺口或超过自动修订边界 | “基本完成”或“应该没问题” |
| 仅生成草稿 | 用户只要方向、片段或未授权正式落盘 | “正式章节已完成” |
| 等待确认 | 缺少会改变结局、人物命运、联网或写入范围的决定 | 自行替用户裁定 |
| 检测失败 | 输入错误、工具异常、网络/API 失败 | “检测通过”或“检测不通过” |

## 权限标签

- **R0 只读**：只读报告、诊断、评测、版本检查，不修改项目。
- **W1 档案写入**：只更新 `mind/`、目录、回顾或报告，不修改正文。
- **W2 正文写入**：修改 `书稿/` 或 `剧本/`，必须说明文件和复测结果。
- **X1 外部调用**：正文、提示词或元数据会离开本机，必须先取得明确同意。
- **U1 技能更新**：只修改技能安装目录；必须先备份，失败回滚。

回执中至少写出一个权限标签。复合请求如果同时包含 W2、X1 或 U1，必须拆成阶段，不得把多个高风险动作伪装成一个普通步骤。

## 四种最短回执

### 正常写作

```text
状态：已完成
主流程：标准级续写第12章
实际变更：书稿/第012章_XXX.md；mind/章节目录.md；mind/回顾/第012章回顾.md（W2）
校验证据：check_chapter.py 退出码 0；30 项语义复核完成
未执行项目：未调用外部检测
风险/待确认：无
下一步：【断点】下一章第13章
```

### 只读审校

```text
状态：已完成
主流程：只读审校第12章
实际变更：未修改项目文件（R0）
校验证据：发现 3 项，已列出位置、证据和严重度
未执行项目：未修订正文
风险/待确认：是否授权按问题修复
下一步：回复“按问题修复第12章”
```

### 外部检测未授权

```text
状态：等待确认
主流程：朱雀 AI 检测
实际变更：未修改项目文件（R0）
校验证据：本地检查已完成；外部 API 未调用
未执行项目：朱雀未运行
风险/待确认：正文将发送至第三方服务（X1）
下一步：明确回复“同意发送正文检测”或改用本地检测
```

### 技能更新失败

```text
状态：检测失败
主流程：技能更新
实际变更：当前安装版本未覆盖；旧版备份保留（U1）
校验证据：包校验失败/替换失败，退出码和报告路径已列出
未执行项目：未完成版本切换
风险/待确认：等待可信更新包或稍后重试
下一步：先运行 python tools/update_skill.py --check --json
```
