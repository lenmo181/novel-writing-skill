# 升级后的小说创作架构（v7.52）

## 模块责任

| 模块 | 输入 | 输出 | 调用时机 | 失败处理 |
|---|---|---|---|---|
| 项目初始化 | 书名、题材、平台、目标字数 | 四级大纲、七档案、场景锚点模板、章节任务卡目录 | 开新书/接入空项目 | 只创建缺失文件；字段未确认时保留 `[待补充]` |
| `chapter_brief.py` | 章纲、卷纲、场景纲、上一章正文/回顾、角色快照、时间线、伏笔、剧情锁 | `mind/章节任务卡/第XXX章任务卡.json` 或 Markdown | 每章写前 | 缺章纲、场景纲、上一章事实或目标时返回 `needs_input`，不生成虚构事实 |
| 上下文包 | 任务卡、canonical 档案、当前章和最近章节 | 带来源 SHA-256 的 JSON/Markdown 包 | 任务卡之后、正文之前 | 按预算截断并标明来源；需要完整事实时按路径回读 |
| 正文生成 | 任务卡、上下文包、章节写作提示词 | 章节正文文件 | 写作阶段 | 只在任务卡 `ready` 且卷界已明确后写；不改已完成章 |
| `scene_continuity.py` | 场景纲、角色状态快照 | 结构问题 JSON/Markdown | 写前预检、写后 Gate | P0/P1 机械问题阻断；旧项目缺扩展列先 warning，迁移后再 strict |
| 章节机械校验 | 正文 | 30 项中的脚本硬卡结果 | 正文落盘后 | 失败就地局部修复，复测前不更新完成断点 |
| 语义审校 | 正文、任务卡、上下文 | 第14-30项 status/evidence/quote | 机械校验后 | `revise/blocked` 不能交付；`weak` 只能继续草稿，不能当正式交付 |
| 记忆更新 | 实际正文、审校结果、任务卡前后状态 | 角色/时间线/事实/伏笔/回顾更新 | 审校通过后 | 不确定事实标 `needs_review`；冲突分为错误、谎言、认知差异、设定变更或未知 |
| 修复编排 | 审稿队列、快照、diff | 局部修复任务包、复检报告 | 出现问题时 | 默认只读；正文写入必须显式 `--apply`，保留快照并做二审 |

## 标准调用顺序

```text
项目体检
  -> 生成章节任务卡
  -> scene_continuity 预检
  -> context_pack
  -> 读取完整写作提示词
  -> 生成正文并落盘
  -> check_chapter
  -> scene_continuity + continuity_check + project_health
  -> 第14-30项语义审校
  -> 局部修复 / diff / 复检
  -> 从实际正文抽取事实并更新 mind
  -> chapter_readiness
  -> 输出断点
```

## 数据优先级

用户明确要求 > `mind/剧情走向锁定.md` > 已写正文和单章回顾 > 角色/世界观设定 > 卷纲/章纲/场景纲计划 > 推断。

计划不得改写成事实。任务卡中的 `previous`、`sources` 和 SHA-256 用于证明写作依据；语义审校中的正文引文用于证明判断依据。

## 写入边界

- `chapter_brief.py` 默认只输出；`--write` 只写 `mind/章节任务卡/` 或显式 `--out`。
- `scene_continuity.py`、`context_pack.py`、`chapter_readiness.py` 和连续性工具只读。
- 修正文前先 `snapshot_project.py`；自动机械修复必须明确 `--apply`，不自动整章重写。
- 外部同类小说研究和朱雀检测仍需用户明确联网/外发授权。

## 失败语义

`needs_input` = 写前资料不足；`warning` = 兼容旧项目或需语义判断；`error` = 明确机械矛盾；`revise/blocked` = 语义证据未通过；`weak` = 只能继续草稿，不是交付结论。
