# 开源小说工作流融合手册（v7.34）

> 本手册记录本技能从公开开源项目吸收的工作流模式、验证边界和许可证处理方式。
> 本技能只实现原创适配层，不复制第三方源代码、提示词包、题材包或受版权保护的正文。

## 一、融合结论

v7.34 在已有五条能力上补齐三个工程入口：

1. **先建上下文包，再写正文**：把设定、档案、章纲、最近章节和单章回顾按来源打包，并记录 SHA-256。
2. **先做项目体检，再启动续写**：目录骨架、章节编号、章节目录、进度行和剧本覆盖率先查清。
3. **写后做连续性检查**：角色首末出场、伏笔埋设/回收章、时间线顺序、目录标题和单章回顾覆盖率机械核对。
4. **修改必须可对照、可回滚**：大修前做项目快照，修改后生成章节 diff；删除比例超过 10% 时必须复核伏笔、钩子和因果锚点。
5. **本地优先、外部可选**：上下文整理、快照、体检和差异分析全部离线完成；任何第三方模型或检测 API 仍需用户明确授权。
6. **先建标准项目，再做健康汇总**：`tools/init_project.py` 只补缺失文件，`tools/project_health.py` 汇总结构、连续性、实体和审校待办。
7. **实体索引只读生成**：`tools/entity_index.py` 从已有角色档案读取姓名、别名和关系，按正文统计出场，不把陌生称呼自动写成新角色。

## 四、许可证防线

- 不把第三方仓库的源码、README 大段原文、提示词包、训练数据或小说正文复制进本技能。
- MIT 项目只表示其代码在满足许可证条件下可复用，不等于可省略来源，也不等于其数据集/示例正文可再分发。
- GPL/AGPL 项目的产品思路可以研究；本技能 v7.27 采用独立实现，避免把其代码链接进标准库工具。
- 开源项目的“本地模型支持”不代表本技能默认联网或默认发送正文；外部服务仍按《运行时兼容》执行用户授权和隐私确认。
- 任何由用户提供的小说正文、拆书样本和文风样本仍只作项目内私有参考，不写入公开技能包。

## 五、使用顺序

### 写第 X 章前

```text
python tools/project_audit.py <项目根>
python tools/continuity_check.py <项目根>
python tools/context_pack.py <项目根> --chapter X --out <项目根>/mind/上下文包_第X章.md
```

### 大修或批量改稿前后

```text
python tools/snapshot_project.py <项目根> --label before-rewrite
python tools/chapter_diff.py <旧章> <新章> --out <项目根>/mind/第X章差异.md
python tools/continuity_check.py <项目根>
```

### 结论边界

这些工具只负责可重复的结构检查、来源追踪和版本保护，不替代作者对动机、信息差、文学效果和平台风险的最终判断；发现问题默认报告，不静默改写档案。

### 当前仍未实现的候选功能

- 研究来源台账与引用反查：价值高，但需要先约定来源字段和隐私/联网边界，下一轮再做 `references/研究来源.md` + 校验器。
- 场景/情节卡的交互式看板：现有 `大纲/场景纲.md` 与离线看板可承载数据，暂不引入 GUI；后续可增加 Markdown 卡片导出。
- EPUB/PDF/有声书发布链：外部工具链和字体环境差异较大，先保留 Zettlr/NovelKit 经验为路线，不把第三方运行时塞进基础技能。
- MCP server、SQL 事件账本和免 Python 交接包：适合独立插件或可选扩展，当前标准库工具已覆盖核心连续性需求。

本节记录的是公开资料的功能差距，不代表第三方项目的全部质量或未来维护承诺；许可证和仓库状态以对应仓库当前 LICENSE 与提交记录为准。

### 7.3 本轮集成的口径边界

- **不新增第 31 项校验**：30 项分级（脚本硬卡 13 + AI 语义 17）保持不变，
  新增能力是既有校验项的**取证与定位补充**。
- **全部新增项为警告级或只读诊断**，不新增硬卡——量化指标误伤成本高于收益。
