# 连载记忆手册（三层回顾归档 + 信息差矩阵 + 连续性审计）

> 触发：`写回顾` / `阶段回顾` / `断更复写` / 一键生成每5-15章自动触发。来源：PromptLibrary 回顾链路方法论整合。
> 解决的问题：**mind/ 七档案是"状态快照层"（谁在哪、知道什么），但不含"叙事因果层"（为什么发生、怎么演变成这样）**。长跑几十章后，快照能保证不穿帮，却保证不了"因果链不断、信息差不塌、伏笔不悬空"——回顾层补这块。

## 两层记忆的分工（不要混、不要省）

| 层 | 文件 | 记什么 | 每章成本 |
|----|------|--------|---------|
| 状态层 | mind/ 七档案 | 当前快照：位置/持有/数值/知情/伏笔编号 | 必做，字段级更新 |
| 叙事层 | mind/回顾/ | 因果链：事件为什么发生、改变了什么 | 必做单章回顾（微型），每5-15章做阶段回顾 |

## 单章回顾（微型版，每章第五步顺产出，150-300字）

写完一章、更新完 mind/ 七档案后，在 `mind/回顾/第XXX章回顾.md` 落一份微型回顾。**固定六栏，不许自由发挥**：

```
## 第XXX章回顾
- 一句话：（≤50字，起因+结果+留下的悬念）
- 关键事件：3-6条，每条一句话（冲突+行动+结果），按时间序
- 状态与关系变化：谁的状态/关系变了、从什么变成什么（只写有变化的）
- 信息差变动：谁新知道了什么 / 谁仍不知道 / 谁产生了误解
- 伏笔变动：新增（编号）/ 推进（编号）/ 回收（编号）
- 下章承接：结尾场景、未了结冲突、必须延续的状态（伤势/物品/承诺）
```

铁律：只记录剧情事实，不评价文笔；不虚构正文没有的信息；**严格区分客观事实、角色认知、误解、未揭露信息**四类（写的时候打标签：[事实]/[认知]/[误解]/[未揭露]）。

## 阶段回顾（每5-15章或单元/卷边界触发）

输入=本阶段全部单章回顾；输出=`mind/回顾/阶段回顾_第X-Y章.md`。不是拼接摘要，是**重组因果链**。

### 融合六原则

1. 只依据单章回顾整理，不得补写原文不存在的内容
2. 不逐章流水账——把散落各章的事件重组成完整因果链（"因为A→人物做了B→导致C"，每条主线整理出：起因/触发/选择/升级/结果/遗留问题）
3. 重复信息去重合并（人物身份、固定关系、同一伤势、同一任务只写一次）
4. 同一伏笔的多次推进合并为一条**生命周期记录**：首次出现→再暗示→新线索→被察觉→部分揭露→完全回收（标注状态；可能二次反转的单独标出）
5. 同一信息在阶段内发生过变化的，写清：最初状态→中间变化→最终状态；**不得用后期信息篡改角色当时的认知**
6. 不同章回顾之间有冲突→**不许擅自选定版本**，在"连续性问题"节标出并上报用户裁定

### 阶段回顾固定结构（十节）

```
# 第X-Y章阶段回顾
1. 基本信息：阶段名/覆盖章/主要地点/视角人物/阶段作用
2. 一句话概括（≤100字）
3. 剧情总览（300-800字，带因果，不逐章复述）
4. 核心剧情线：每条线=初始状态→触发→发展→关键转折→关键选择(谁/为何/结果)→阶段结果→遗留问题→对后续影响
5. 人物阶段变化：每角色=开始状态→主要经历→关键选择→新信息/新误解→结束状态（含"目前知道/不知道/误解"三行）+2-3句变化轨迹总结；没变化就写"未发生明确变化"，不强行成长
6. 信息差矩阵（见下）
7. 伏笔池：新增/推进/部分回收/完全回收/主要秘密（每条含知情者与不知情者）
8. 阶段结束快照：时间/地点/在场人物/各角色身心状态/未解决冲突/未完成行动/下一阶段必须立刻承接的最后场景
9. 下一阶段续写硬约束：必须保持 / 必须继续体现（伤势情绪信息差）/ 不能让角色提前知道 / 不能被无故改变 / 不能直接解决（仍需铺垫的）/ 可以自然推进
10. 连续性问题 + 检索关键词（15-30个：人物/地点/事件/关系/物品/伏笔）
```

### 信息差矩阵（第6节格式，长篇翻页引擎的地基）

| 角色 | 现在知道 | 还不知道 | 相信但不一定对（误解） |
|------|---------|---------|----------------------|
| 主角 | … | … | … |
| 配角A | … | … | … |
| 读者 | …（上帝视角额外知道什么） | — | — |

- 误解必须写**来源**（哪章哪事件造成的）和**可能后果**——这是后续戏剧冲突的库存
- 已在后期揭露的信息，不许写成"所有人一开始就知道"
- 与主文件「期待感体系·信息差三层」联动：写章前查此矩阵定知情范围，写完更新

## 三档压缩摘要（阶段回顾末尾附）

- **超短**（≤100字）：章节列表速览用
- **标准**（300-500字）：日常归档、快速恢复剧情用
- **续写摘要**（600-1000字）：只留下一阶段续写要用的——当前局面/人物状态/关系/信息差/未决问题/结尾场景/续写约束；**不得包含与后续无关的支线细节**

## 用法场景

| 场景 | 动作 |
|------|------|
| 跨会话/断更复写 | 读"最近一份阶段回顾 + 最新单章回顾 + mind/快照"即动笔，不重读早期正文 |
| 一键生成长跑 | 每完成5-15章做一次阶段回顾；后续章节以阶段回顾替代早期正文回读（省上下文，防记忆稀释） |
| 大修某章 | 先调该章单章回顾+所在阶段回顾，事件清单当"不可破坏骨架"对照改 |
| 连续性审计 | `检查逻辑漏洞`时以阶段回顾第10节清单逐条过（见下） |
| 伏笔排查 | 阶段回顾第7节伏笔池 + mind/伏笔追踪表双查：埋了没回收的、回收了没登记的 |

## 连续性审计清单（15项，阶段回顾时逐条过）

同一事件描述冲突 / 时间顺序冲突 / 地点变化缺过程 / 人物位置不一致 / **人物知道了不应知道的信息** / **人物忘了已经知道的信息** / 同一物品多个持有人 / 伤势无故消失或反复 / 能力规则变化 / 称呼·专有名词不统一 / 关系变化缺过渡 / 承诺·任务·伏笔遗漏 / **已回收伏笔被重新当悬念** / **未确认信息被写成确定事实** / 章尾与下章开头接不上。

发现问题→记入"连续性问题"节→能由正文判定的修档案，不能判定的**上报用户裁定**。

## 成本控制

- 单章回顾必须微型（150-300字），膨胀=失败——它是给 AI 续读的，不是给读者看的
- 阶段回顾控制在2000字内；超了先砍剧情总览，不砍信息差/伏笔池/硬约束
- 检索关键词是为了 grep 正文定位原文用的，宁多勿漏
